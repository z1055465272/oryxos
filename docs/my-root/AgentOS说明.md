### 企业为什么需要一个私有可控的Agent OS 底座



1、数据不出企业（核心业务不能跑在SaaS上）

2、完全可审计（每一步都要留痕、可追溯）

3、纳入IT治理（走企业现有安全于合规流程）

4、技术栈对齐（多为java）

### Agent OS与 现有产品对比

openClaw：node写的、个人、开发者优先、企业安全治理较弱、CVE、恶意skill、凭证收割

hermes：python写的、偏个人和团队，自进化skill、多租户RBAC/SSO/审计仍是空白、当企业底座仍需二次开发

OryxOs：私有部署、完全可审计、day one治理与安全、拿来即用

### Agent OS 定位

部署起来后，业务方在上面写skill/plugin，就有了一个agent

LLM调用、message对接、记忆压缩、运行调度上层都不需要关注，底座已经实现好了，业务直接调用agent即可

### Agent OS整体架构

| 接入层  | cli、webService、REST API  消息进出通道                      |
| ------- | ------------------------------------------------------------ |
| 引擎 层 | ReActLoop agent大脑                                          |
| 能力层  | ProviderService(提供商服务)、MemoryService(记忆服务)、ToolRegistory(工具注册服务) |
| 基础层  | ProfileLoader、ContextLoader、SessionManager、SQLLite、ConfigLoader |

### Agent OS 安全

| **来源受控** | 不做开放的skill市场、skill/Tool要注册、审核、签名  |
| ------------ | -------------------------------------------------- |
| 最小权限     | 文件、网络、shell要收紧、按需开放                  |
| 强制沙箱     | Tool隔离执行、多租户之间 完全隔离                  |
| 凭证不落地   | 对接企业KMS\Vault，使用全程可审计                  |
| 注入防御     | 记忆写入、工具输出过 安全扫描、防prompt注入、外泄  |
| 全链路审计   | 谁、合适调用了什么、访问了什么、结构化留痕、接SIEM |

### Agent OS 从单机到分布式

| OS底座单机私有化部署 | 一个OS实例跑一组Agent，最易接入、最易纳入现有审计与运维      | 当前阶段 |
| -------------------- | ------------------------------------------------------------ | -------- |
| OS底座分部署         | 实例无状态、状态外置Redis、PG、对象存储，多实例高可用，水平扩展 | 未来实现 |
| 分部署Agent协作      | 多个oryxOS节点上的Agent跨节点发现、委托、协同、分布式Agent OS | 未来实现 |
